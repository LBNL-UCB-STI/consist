LinkML Provenance Graph Implementation Plan¶

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Ship the experimental 0.1.0 Consist LinkML provenance graph and optional cache-aware binding module as checksummed offline release assets.

Architecture: provenance.yaml becomes the durable graph vocabulary and adds a document envelope for explicit context inheritance. binding.yaml imports that vocabulary for requested/effective/cache-source invocation facts. The existing developer-only release script emits source, merged, and generated reference assets for both modules.

Tech Stack: LinkML 1.11.1, PyYAML/JSON Schema through the existing LinkML development environment, pytest, Ruff, uv.

Global Constraints¶

  • Keep schema version exactly 0.1.0; it is independent of package version 0.4.0.
  • LinkML remains a development-only dependency; ordinary import consist loads neither linkml nor linkml_runtime.
  • Only sha256:file:<digest> and sha256:manifest-v1:<digest> identities are attestable.
  • Context identity is (namespace, local ID); locator is never identity-bearing.
  • Omitted per-record context inherits the enclosing provenance document context.
  • Keep all new role, binding-parameter, implicitness, optional parent, and optional producing-run evidence optional.
  • Preserve the current dirty worktree; do not stage or commit unrelated files.
